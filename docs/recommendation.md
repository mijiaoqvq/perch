# 栖景 0.8 推荐架构

目标是逐渐识别偏好、保留探索，并让每次判断可解释。模型运行在本机；它估计内容与反馈的关联，不推断某个标签就是喜欢或不喜欢整张图的原因。

## 1. 将反馈、展示和下载分开

| 记录 | 用途 | 不代表什么 |
| --- | --- | --- |
| 喜欢 / 不喜欢 | 明确正负证据，对称处理 | 收藏不额外再加一次喜欢 |
| 收藏夹导入的喜欢 | 明确正面证据，与本地反馈去重 | 重复同步不增加次数；本地取消优先 |
| 展示 | 前台图库或预览连续可见至少 10 秒；或确认被设为 / 正在用作桌面 | 看过不等于喜欢，展示本身不加分 |
| 自然淘汰 | 已展示、未评价，且被成功更新引发的普通清理实际删除 | 手动清理、导入清理、失败、不喜欢换图不算接受 |
| 成功下载 | 持久化探索计数和近期内容多样性 | 获取候选、元数据、失败或重复文件不算成功 |

状态优先级：规格 / 手动移除 → 手动偏好 → 当前明确反馈 → 弱接受。喜欢、收藏、网站导入按图片 ID 合并；不喜欢覆盖同图正面状态；当前明确反馈覆盖同图弱接受。取消喜欢会阻止旧的弱接受再次生效。弱接受只记一次，重复导入或重新删除不刷新其时间。

界面只检测自己的前台可见卡片和预览，不读取其他应用的浏览行为。切走、隐藏卡片后连续展示计时重置；不从下载记录猜测展示。系统壁纸查询沿用现有保护流程，仍先保护当前壁纸，再判断是否能清理。

新增 `exposures`、`accepted`、`deliveries` 和导入日期表；现有图片、喜欢、收藏、不喜欢及手动标签数据保留。升级不会从旧的 `seen` 表补造接受记录。已有本地反馈使用原日期；旧的仅学习导入若缺失日期，以迁移时间为起点，无法还原未知的历史时间。

## 2. 明确证据模型

标签与色调共用 `perch/learning.py`，避免两处规则逐渐不一致。

1. 全局至少 20 张有可用元数据的明确反馈后才启用自动推断。规格、移除、未评价、元数据缺失均不能凑数。标签和色调分别校准。
2. 每张图对同一标签只记一次。同图同色系取前三主色中的最高强度，依次为 1、0.55、0.3。
3. 明确证据按 `2^(-年龄 / 90天)` 减弱；界面仍显示原始次数。手动偏好不衰减，照片删除不删除反馈。
4. 单个特征至少出现于 3 张明确评价图片。这只是最低入口，还需要通过不确定性判断。少量同向反馈不会立即被当成确定偏好。

对衰减后的正负证据质量 `P, N`，令 `n=P+N, p=P/n, z=1.645`：

```text
center = (p + z²/(2n)) / (1 + z²/n)
radius = z × sqrt(p(1-p)/n + z²/(4n²)) / (1 + z²/n)
low = center - radius
high = center + radius

low > 0.55  → 正向强度 (low-0.55)/0.45
high < 0.45 → 负向强度 -(0.45-high)/0.45
其他        → 0，暂时中立
```

这是以 [NIST 所述 Wilson 区间](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm) 为基础的不确定性保护，加上 45%–55% 的实用中立区。衰减权重、色调强度、图片共现和用户选择都会破坏独立二项样本假设，因此这里**不宣称统计覆盖率，也不是“喜欢概率”预测**。

若存在至少 5 份不含该特征的明确证据，还比较含 / 不含特征图片的平滑正面比例 `(P+2)/(P+N+4)`。方向差异不足 0.05 时保持中立；有差异时按 `min(1, (方向差异-0.05)/0.25)` 缩小强度，最后乘 `n/(n+4)`。这能减少“普遍存在的标签替整张图背锅”，但不能消除相关标签之间的归因歧义。

例如，在已经完成全局校准时：

| 明确次数 | 没有额外背景对照时的判断 |
| --- | --- |
| 5 喜欢 / 4 不喜欢 | 暂时中立 |
| 4 喜欢 / 5 不喜欢 | 暂时中立 |
| 5 喜欢 / 6 不喜欢 | 暂时中立 |
| 3 喜欢 / 0 不喜欢 | 暂时中立，证据仍少 |
| 4 喜欢 / 0 不喜欢 | 轻微正向，尚不足以触发辅助搜索 |
| 20 喜欢 / 4 不喜欢 | 正向，强度再受背景对照和时间影响 |

手动“更多推荐”设为 +1，“减少推荐”设为 -1.5；这里的非对称是明确手动指令的强度，不再用于自动反馈计数。规格和移除标签始终为 0，包括弱信号和内容相似度。

## 3. 弱接受的硬上限

“没有不喜欢”也可能意味着没有看过，所以展示是前提。正常更新淘汰后才产生弱接受，收藏和喜欢不会额外叠加它。

每张合格图片提供 0.05 份弱证据，按 30 天半衰期减弱。每个特征至少 3 张合格弱接受后才提供微调；该特征弱证据总预算最多 0.5，映射到最多 0.04 的排序加分。

```text
weak(feature) = 0.04 × min(0.5, Σ(0.05 × 衰减 × 色调强度)) / 0.5
```

约束同时存在：

- 不能完成 20 张明确反馈的校准，也不改变喜欢次数。
- 不改变明确偏好的方向或界面的中立分组；纯弱接受标签保持“暂时中立”，浮层单独说明它只是弱排序参考。
- 含负面反馈、且明确模型尚未支持正向的特征不使用弱加分。
- 手动设置和规格 / 移除名单覆盖弱信号。
- 不进入标签或色调辅助搜索列表。
- 标签与色调弱分合并后，**每张候选总弱增益仍最多 0.04**。候选明确分小于 0 时不加弱分。

因此，累积一千张相同题材的被动接受，也不能让它获得无限增长的分值、压倒明确不喜欢，或自己把候选来源变成该题材搜索。阈值为保守的工程默认值，未声称经过用户偏好准确率标定。

## 4. 候选来源、排序与探索

```text
原有搜索条件 ── 普通发现 ─────────┐
明确正向偏好 ── 少量辅助搜索 ─────┤
                                ↓
严格资格与历史去重 → 有界候选池 → 标签 / 色调评分 → 近期相似内容降序
                                ↓
                  每第四次成功下载优先普通发现
                                ↓
                     验证文件 → 保存 → 记录成功
```

保留 Anime、SFW、尺寸、比例、显式关键词和显式色彩过滤。标签减少推荐是软排序；明确不喜欢的图片 ID 和已下载过的内容仍排除。

有足够普通候选时，初始 12 个候选中至少 6 个来自普通发现。辅助搜索只使用明确分至少 0.08 的偏好：最多从前 8 个正向标签轮换选 2 个、前 4 个色调选 1 个。手动关键词存在时不改写关键词，只对原搜索结果排序；显式色彩过滤不被学习色调替换。

标签分 = 最强正向分 + 最强负向分。同义、共现标签不能靠数量无限叠加，添加中立或未知标签也不降低分数。色调为有效偏好的主色强度加权平均，组合为 `标签分 + 0.65 × 色调分 + 有上限弱分`。

以内容标签和主要色系计算加权 Jaccard 相似度，再减去 `0.2 × 与最近12张成功下载的最大相似度`。被移除、规格及保持中立的手动色调不参与相似度。这个有界降序不硬禁任何主题；它借鉴相关性与新颖性共同排序的思路，便于在接近的候选之间选择不同内容。探索槽不按这些分值重排，直接采用普通发现顺序。

探索计数只在图片验证并成功保存后增加，写入 SQLite，跨批次和重启延续。失败、重复内容不消耗槽位。若探索时池内普通候选耗尽，继续补一个普通候选；整个普通来源耗尽才回退到其他合格候选。即使每次仅更新一张，也能触发第四张探索。普通来源自身可能同质，**来源保障并不等价于全新主题比例保障**。

参考：[Microsoft Research 关于反馈产生方式与推荐偏差的研究](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/WSDM_2019_schnabel_et_al.pdf)。本项目采用可检查的本地规则，没有声称消除了曝光偏差或实现了该论文的算法。

## 5. 失败、撤销与验证

- 标签 / 色调缺失不视为负面；接口失败保留缓存和反馈，后续按现有冷却策略重试。
- 先成功保存替换图，再清理旧图；当前桌面、收藏、排队不喜欢图片仍受原有保护。
- 自然淘汰信号在实际删除成功后记录；清理取消、文件已不在、删除失败不会生成接受。
- 本地取消、手动名单和重复同步优先级不变。恢复自动学习会重新计算当前证据，不恢复旧的错误分数。
- 个性化关闭时使用原始来源，不生成自然淘汰弱反馈或推进推荐探索计数；现有明确记录和手动设置继续保存。

`tests/test_learning.py` 覆盖 5/4 中立、对称性、背景归因、弱反馈上限、不能自行校准或搜索、明确反馈覆盖、衰减、重复清理、当前桌面保护、真实成功下载的探索计数、重启、失败及池内补充普通发现。现有下载、同步、校准、手动名单与清理测试继续执行。`tests/gui_learning.py` 检查中立浮层、弱信号说明、前台可见停留及实际自然淘汰。

这些验证保证实现遵守上述边界，并不保证每张推荐都符合审美。图片标签不完整、标签共现、网站候选偏差，以及无法判断“看见但没评价”的真实原因，仍是模型的限制；手动偏好和探索用于保留用户纠正与发现的空间。
